# Requirements discovery (new products)

Write one line each; infer from the code, data model and domain when AK's
brief is thin, and list what you assumed.

| Question | Why it matters |
|---|---|
| **Vision:** what is the product for, and why does it exist? | sets the direction and tone |
| **Audience:** who uses it, where, on what device, in what state of mind, how often? | decides density, motion level, touch vs pointer, language |
| **Primary journeys:** the 2–4 things users come to do, step by step | decides IA and the main screens |
| **Primary job of the main screen** | the one thing it must make effortless |
| **Content and data:** what's shown, how much, how often it changes, real or live data? | decides layout, tables vs cards, loading strategy |
| **Category:** marketing site, SaaS, AI app, enterprise/admin, consumer, mobile, desktop, internal tool | narrows the fitting design directions |
| **Platform and devices:** web (which sizes), iOS/Android, desktop; offline needs | decides responsive strategy and platform conventions |
| **Brand assets:** logo, colours, fonts, Figma file, existing products to match | Figma or existing brand wins over a new invention |
| **Languages:** English only, or Burmese/Chinese/Malay/Tamil too | type choices, line heights, layout tolerance |
| **Accessibility needs:** WCAG 2.2 AA by default; any specific users | requirements for components |
| **Constraints:** stack, existing design system, performance budget, deadlines, legal | what's realistic |
| **Success:** how will we know it works? | what to verify |

For AI products also note: what the AI does, which states users will see
(thinking, tool use, streaming, failure, cancellation), and what users need
to trust it (sources, confirmations, undo).

Lasting answers — users and setting, target screens, languages, themes —
go into `DESIGN.md`.
