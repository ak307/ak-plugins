# Laravel standard template

Use this for every new Laravel project. The baseline is Laravel's official
**React starter kit** (Laravel 13 + Inertia 3 + React + TypeScript +
Tailwind 4 + shadcn/ui + Wayfinder). Create the project with the installer and
keep everything the kit generates; this file adds the backend structure and
naming on top, where past projects drifted apart (lowercase controller names,
1,000-line controllers, `api` vs `Api` folders, JS in one project and TS in
the next).

```
laravel new project-name
# choose: React starter kit, Pest, MySQL, Laravel Boost: yes
```

Laravel Boost gives Claude a Tinker tool (runs any PHP) and database tools
that use the app's `.env`. Use it only while `.env` points at a local
database. In a project connected to production, remove the Boost MCP server
from the project's MCP config (or disable its Tinker and database tools) —
the production guard also asks before those tools run.

## 2. What goes where

### Controllers — thin, resourceful

A controller method authorises, takes validated input from a FormRequest,
calls an Action (or Eloquent directly for plain reads), and returns an
Inertia page, redirect or resource. If a method needs more than ~20 lines, the
logic belongs in an Action. Prefer the seven resource actions
(`index, create, store, show, edit, update, destroy`); for extra operations add
a small method (`approve`) or a separate invokable controller.

```php
use App\Http\Resources\LeaveRequestResource;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Gate;
use Inertia\Inertia;

class LeaveRequestController extends Controller
{
    public function index(Request $request): Response
    {
        Gate::authorize('viewAny', LeaveRequest::class);

        $leaveRequests = LeaveRequest::query()
            ->visibleTo($request->user())
            ->with('staff')
            ->latest()
            ->paginate(20);

        return Inertia::render('leave-requests/index', [
            'leaveRequests' => LeaveRequestResource::collection($leaveRequests),
        ]);
    }

    public function store(StoreLeaveRequestRequest $request, SubmitLeaveRequest $submitLeaveRequest): RedirectResponse
    {
        Gate::authorize('create', LeaveRequest::class);

        $submitLeaveRequest->handle($request->user(), $request->validated());

        Inertia::flash('toast', ['type' => 'success', 'message' => __('Leave request submitted.')]);

        return to_route('leave-requests.index');
    }

    public function approve(LeaveRequest $leaveRequest, ApproveLeaveRequest $approveLeaveRequest): RedirectResponse
    {
        Gate::authorize('approve', $leaveRequest);

        $approveLeaveRequest->handle($leaveRequest, request()->user());

        Inertia::flash('toast', ['type' => 'success', 'message' => __('Leave request approved.')]);

        return back();
    }
}
```

Every controller method authorises first — `Gate::authorize(...)` with the
model's Policy — and list queries are scoped to what the user may see
(`visibleTo()` scope). The kit's base `Controller` has no `authorize()`
helper.

**Inertia props are public.** Everything passed to `Inertia::render` is in
the page's HTML, readable by the user. Pass Resources that list exactly the
fields the page needs — never models or paginators of models, which send
every non-hidden column (and loaded relations) to the browser. Success/error messages use the kit's toast flash
(`Inertia::flash('toast', ...)`), not `->with('success', ...)`, which the
frontend never shows.

### Actions — business operations

One class per operation, named verb + noun, with a single `handle()` method.
Multi-step writes go in a transaction.

```php
namespace App\Actions\LeaveRequests;

class ApproveLeaveRequest
{
    public function handle(LeaveRequest $leaveRequest, User $reviewer): LeaveRequest
    {
        return DB::transaction(function () use ($leaveRequest, $reviewer) {
            // Lock the row, then check: two approvers clicking at once can't both pass.
            $leaveRequest = LeaveRequest::whereKey($leaveRequest->id)->lockForUpdate()->firstOrFail();

            if ($leaveRequest->status !== LeaveStatus::Pending) {
                throw new LeaveRequestException('Only pending requests can be approved.');
            }

            $leaveRequest->update([
                'status' => LeaveStatus::Approved,
                'reviewed_by' => $reviewer->id,
                'reviewed_at' => now(),
            ]);

            return $leaveRequest;
        });
    }
}
```

**Status changes = lock, check, write — in one transaction.** Checking the
status before the transaction, or without `lockForUpdate()`, lets a double
click or two approvers approve twice.

### Policies — who may do what

```php
class LeaveRequestPolicy
{
    public function view(User $user, LeaveRequest $leaveRequest): bool
    {
        return $leaveRequest->staff_id === $user->id || $leaveRequest->staff->manager_id === $user->id;
    }

    public function approve(User $user, LeaveRequest $leaveRequest): bool
    {
        // The staff member's manager approves; nobody approves their own request.
        return $leaveRequest->staff->manager_id === $user->id && $leaveRequest->staff_id !== $user->id;
    }
}
```

Adapt the rule to how the project models approvers (roles, departments),
but always check the record, not just the role. Pest tests cover each
action for the owner, another user (403) and a guest.

Actions are injected into controller methods, jobs and commands. `Services/`
holds only clients for external systems (Outlook, SMS gateway, an LLM server).

### FormRequests — all validation

Never validate in the controller. `Store<Model>Request` / `Update<Model>Request`
with `rules()`; authorisation stays in policies. Files the kit generated keep
their own names (`Requests/Settings/ProfileUpdateRequest`).

### Models

Use the same style as the kit's `User` model: PHP attributes for mass
assignment and hidden fields, `casts()` (with enum casts), relationships and
small scopes (e.g. `scopeVisibleTo(Builder $query, User $user)` returning
only rows the user may see). No business workflows inside models. In
`AppServiceProvider::boot()`, call `Model::preventLazyLoading(! app()->isProduction())`
so N+1 queries fail loudly in development.

### Enums

`app/Enums/LeaveStatus.php`: string-backed, TitleCase cases
(`case Pending = 'pending';`), plus a `label(): string` method for display.
Cast model attributes to them.

### Routes

```php
// routes/web.php
Route::middleware(['auth', 'verified'])->group(function () {
    Route::resource('leave-requests', LeaveRequestController::class);
    Route::post('leave-requests/{leave_request}/approve', [LeaveRequestController::class, 'approve'])
        ->name('leave-requests.approve');
});
```

`Route::resource('leave-requests')` names the parameter `{leave_request}`;
custom routes on the same resource use the same name.

### Frontend pages

- `Inertia::render('leave-requests/index')` maps to
  `resources/js/pages/leave-requests/index.tsx`. Layouts are chosen by page
  path prefix in `app.tsx`, so a new page folder may need a layout entry there.
- Link and submit with **Wayfinder** imports — `import { index } from '@/routes/leave-requests'`
  or controller actions from `@/actions/...` — never hard-coded URLs or
  `route()`.
- Page props are typed with a type from `resources/js/types/`. Reuse
  `components/ui` (shadcn) before writing new components.

### API (only when needed)

`php artisan install:api` (Sanctum + `routes/api.php`). Controllers in
`Http/Controllers/Api/`, responses through `Resources/`. Internal APIs are
unversioned; an API used by mobile apps or other teams goes under
`Api/V1/` with the `/api/v1` prefix.

## 3. Naming rules

| Thing | Rule | Example |
|---|---|---|
| Project folder | kebab-case | `leave-portal` |
| Model | singular PascalCase | `LeaveRequest` |
| Table | plural snake_case | `leave_requests` |
| Controller | `<Model>Controller`, PascalCase always | `LeaveRequestController` (never `leaveRequestController`, `createLeaveController`) |
| API controller | same name under `Controllers/Api/` | `Api\LeaveRequestController` |
| Action | verb + noun, under `Actions/<Area>/` | `Actions\LeaveRequests\ApproveLeaveRequest` |
| FormRequest | `Store<Model>Request`, `Update<Model>Request` | `StoreLeaveRequestRequest` |
| Policy | `<Model>Policy` | `LeaveRequestPolicy` |
| Resource | `<Model>Resource` (API responses and Inertia props) | `LeaveRequestResource` |
| Enum | singular PascalCase, TitleCase cases | `LeaveStatus::Approved` |
| Route URIs | plural kebab-case, snake_case parameter | `/leave-requests/{leave_request}` |
| Route names | `<uri>.<action>` | `leave-requests.approve` |
| Page files | `pages/<resource-kebab>/<action>.tsx` | `pages/leave-requests/edit.tsx` |
| Components | kebab-case file, PascalCase export (kit style) | `leave-status-badge.tsx` → `LeaveStatusBadge` |
| Methods / variables | camelCase | `$leaveRequest`, `approveLeaveRequest` |
| Columns | snake_case | `start_date`, `reviewed_by` |
| Tests | `tests/Feature/<Area>/<Behaviour>Test.php` | `LeaveRequests/ApproveLeaveRequestTest.php` |

## 4. Adding a new feature — checklist

1. `php artisan make:model LeaveRequest -mfs` (model, migration, factory, seeder).
2. Enum(s) in `app/Enums/` with `label()`, cast in the model.
3. `php artisan make:request StoreLeaveRequestRequest` (and Update).
4. `php artisan make:policy LeaveRequestPolicy --model=LeaveRequest`.
5. Actions in `app/Actions/LeaveRequests/` for anything beyond plain CRUD.
6. `php artisan make:controller LeaveRequestController --resource`.
7. Routes in `routes/web.php` (and `api.php` for JSON).
8. Pages in `resources/js/pages/leave-requests/`, type in `resources/js/types/`, Wayfinder imports for links/forms.
9. Pest feature tests in `tests/Feature/LeaveRequests/` (they run on the
   test database below, never the `.env` one).
10. New config → `config/*.php` reading `env()`, and `.env.example`.
11. `composer ci:check` passes (Pint, Larastan, frontend checks, tests).

## Tests never touch the app's database

`RefreshDatabase` and `DatabaseTruncation` empty every table in the database
the tests connect to. Unless `phpunit.xml` (or `.env.testing`) overrides it,
that is the database in `.env` — which may be production. Every project
sets the test database explicitly and guards it:

```xml
<!-- phpunit.xml, inside <php> -->
<env name="APP_ENV" value="testing"/>
<env name="DB_CONNECTION" value="sqlite"/>
<env name="DB_DATABASE" value=":memory:"/>
<env name="MAIL_MAILER" value="array"/>
<env name="QUEUE_CONNECTION" value="sync"/>
```

(For MySQL-specific behaviour, use a local test database instead:
`DB_HOST=127.0.0.1`, `DB_DATABASE=<project>_test`.)

```php
// tests/TestCase.php — refuse to run against anything but a local test database.
// The check runs in setUpTraits(), before RefreshDatabase touches anything.
protected function setUpTraits()
{
    $this->ensureLocalTestDatabase();

    return parent::setUpTraits();
}

private function ensureLocalTestDatabase(): void
{
    $database = config('database.connections.'.config('database.default'));
    $isMemory = ($database['database'] ?? '') === ':memory:';
    $isLocalTestDatabase = in_array($database['host'] ?? '', ['127.0.0.1', 'localhost', 'mysql'], true)
        && str_contains($database['database'] ?? '', 'test');

    if (! $isMemory && ! $isLocalTestDatabase) {
        throw new RuntimeException('Tests must use a local test database. Check phpunit.xml.');
    }
}
```

## 5. Defaults and when to change them

| Decision | Default | Change only when |
|---|---|---|
| Frontend | React starter kit (Inertia + React + TypeScript) | The project is Blade/Livewire already — keep Livewire and use the official Livewire starter kit layout |
| Language | TypeScript (`.tsx`) | Never for new projects |
| Routing in JS | Wayfinder | Never (no Ziggy in new projects) |
| Business logic | Actions | — |
| Database | MySQL | Project already uses another DB |
| Auth | starter kit auth (Fortify: 2FA, passkeys as needed) | SSO required → Socialite provider (Keycloak, Entra) or the WorkOS kit variant |
| API auth | Sanctum | Never |
| Tests | Pest | Project already uses PHPUnit classes |
| Code quality | Pint + Larastan + the kit's frontend check, all via `composer ci:check` | Never |
| AI tooling | Laravel Boost installed | — |
| Queues | database driver (never run a worker on a laptop against a shared database — it takes live jobs) | Redis available and volume needs it |
| Blade | emails and PDFs only | Never for app pages in an Inertia project |
