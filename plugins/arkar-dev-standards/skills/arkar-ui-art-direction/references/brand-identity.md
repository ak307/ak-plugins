# Brand identity

## Sources of identity, in priority order

1. **A Figma design AK provides** — it is the identity. Read it with the
   Figma skills (`figma-design-to-code`, `figma-implement-motion` for
   animated frames), copy its tokens into `DESIGN.md` with the link, extend
   its language to screens it doesn't cover. Don't create or edit Figma files
   unless AK asks.
2. **An existing `DESIGN.md`** — follow it; change it only deliberately and
   record the change.
3. **The product's existing look** — a logo, a component library, consistent
   colours and type: write it into `DESIGN.md` and design within it.
4. **Company brand assets** — CBM red `#AE1A28` is a primary colour only
   when AK asks for CBM branding; where an existing product already uses
   it, keep it in Mode A and ask AK in Mode B. Otherwise the best design for
   the product wins.
5. **A new identity** — chosen with `visual-design-directions.md`.

## Preserving an existing brand while improving it

- Keep: logo, brand colours (possibly re-tuned for contrast), recognisable
  type or a close modern equivalent, names and voice users know.
- Refine: inconsistent use of those assets, contrast failures, cluttered
  layouts, outdated components, missing states.
- When a brand colour fails contrast as text, keep it for large elements and
  fills and derive an accessible darker/lighter variant for text and
  focus — record both.
- Proposals that would change the brand itself go to AK.

## Logo and imagery

- Use the logo files the project has; never redraw or "improve" a real logo.
- Don't invent fake client logos, testimonials, awards or statistics for a
  real company; use clearly marked placeholders.
- Photos of real people only when the project supplies them.

## Fonts

Choosing, bundling and language coverage: `arkar-ui-design-system/references/typography-system.md`.
Keep a brand's existing typefaces (or a close modern equivalent) in Mode A.
